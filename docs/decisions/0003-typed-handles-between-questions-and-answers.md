# 0003 Typed handles between questions and answers

## Context

The TypeSafe API takes a map of question ids to questions and returns a map of the same ids to answers. Nothing on the wire connects a Noul question to a Noul answer, and a Choice answer's option is a string. A client that returns the raw maps leaves every consumer to re-check primitives and re-parse strings, and a typo in an id or an option is found at runtime, if at all.

## Decision

`Questions::noul`, `choice`, `score` and `dynamic_choice` return `Handle<A>` where `A` is the typed answer. `Response::get(&handle)` performs the checked conversion. Choice options over a closed set are a Rust enum implementing `Options`, generated by the `options!` macro, which also produces the request criteria.

## Consequences

- The request and the parser are derived from one definition, so they cannot disagree.
- A primitive mismatch or unknown option is an explicit error with the question id.
- Runtime option sets, such as incident references, use a dynamic Choice that returns strings; the caller maps them, and the boundary is visible in the type.
- The client is slightly more ceremony than a raw JSON call. The saving is every downstream consumer.
